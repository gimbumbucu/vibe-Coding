# [PRD] 커피 주문 웹 앱 (MVP)

## 1. 프로젝트 개요

* **프로젝트명:** 스마트 커피 주문 시스템
* **목적:** 웹 개발 실습을 위한 단일 매장용 실시간 커피 주문 및 매장 관리 시스템 구축
* **핵심 목표:**
* 사용자가 손쉽게 옵션을 선택해 음료를 주문할 수 있는 흐름 제공
* 관리자가 들어온 주문을 실시간으로 처리하고 재고/메뉴 상태를 제어할 수 있는 환경 제공



---

## 2. 타겟 유저 및 페르소나

1. **일반 사용자 (손님):** 카운터 대기 없이 모바일 웹으로 빠르게 음료를 커스텀하여 주문하고, 진행 상황을 확인하고 싶은 사람.
2. **관리자 (바리스타/매장주):** 복잡하지 않은 화면에서 주문을 빠르게 확인·상태 변경하고, 품절 메뉴를 즉시 반영하고 싶은 사람.

## 4. 비기능 요구사항 (Non-Functional Requirements)

* **사용성 (Usability):** 모바일 화면(375px~)을 우선 고려한 반응형 UI (Mobile-First Design).
* **데이터 지속성 (Persistence):** 장바구니 정보 및 **최근 진행 중인 주문 번호(orderId)**는 브라우저 새로고침이나 탭 닫힘 시에도 유지되어 주문 복구가 가능해야 함 (Local Storage 활용).
* **접근 제어 (Security):** `/admin` 경로 접근 시 단순 클라이언트 보호가 아닌, JWT 기반의 서버사이드 미들웨어 검증 및 데이터베이스 자체 보안(Supabase RLS)을 적용하여 철저한 인가(Authorization) 통제.
* **안정성 (Stability):** 서버리스(Vercel) 환경의 연결 끊김(Timeout) 문제를 방지하기 위해 WebSocket 기반의 독립된 실시간 통신 서비스(Supabase Realtime)를 활용하여 안정적인 주문 상태 업데이트 보장.

### C-02 옵션 관리 세부 명세 (Detail Specification)

#### 1. 옵션 분류 체계 (Option Types)

1. **단일 선택 필수 옵션 (Radio Button 형태)**
* **온도:** `HOT` / `ICE` (메뉴별 기본값 설정 지원, 디저트/일부 전용 음료 제외)
* **사이즈:** `Tall` (+0원) / `Grande` (+500원) / `Venti` (+1,000원)


2. **다중 선택/수량 변경 옵션 (Counter / Checkbox 형태)**
* **샷 추가:** 기본 샷 외 추가 (+500원 / 최대 5개)
* **시럽 추가:** 바닐라 시럽, 헤이즐넛 시럽 등 (+500원 / 최대 5펌프)
* **우유 변경:** 일반 / 저지방 (+0원) / 오트유 (+500원) - *단일 선택*
* **얼음/휘핑크림 양:** 안함 / 적게 / 보통 / 많이 (+0원) - *단일 선택*



---

#### 2. 옵션 데이터 및 가격 계산 로직 (Business Logic)

* **최종 항목 단가 계산식:**

$$\text{Item Price} = (\text{Base Price} + \text{Size Extra} + \sum (\text{Option Extra} \times \text{Option Qty})) \times \text{Item Quantity}$$


* **수량 제어 규칙:**
* 필수 옵션은 최소 1개가 선택되어 있어야 장바구니 담기 버튼이 활성화됩니다.
* 수량 옵션(샷, 시럽 등)은 `+`, `-` 버튼으로 조절하며 `0개`일 경우 추가 금액이 청구되지 않습니다.



---

#### 3. 프론트엔드/백엔드 데이터 구조 예시 (Developer Guide)

장바구니에 담기거나 주문 데이터로 전송될 때 옵션 상태는 아래와 같은 구조로 관리됩니다.

```json
{
  "menuId": "m_001",
  "menuName": "아메리카노",
  "quantity": 2,
  "selectedOptions": {
    "temperature": "ICE",
    "size": { "name": "Grande", "extraPrice": 500 },
    "extras": [
      { "optionId": "opt_shot", "name": "샷 추가", "quantity": 1, "unitPrice": 500 },
      { "optionId": "opt_syrup_vanilla", "name": "바닐라 시럽", "quantity": 2, "unitPrice": 500 }
    ]
  },
  "calculatedUnitPrice": 6000, // (4,500 + 500 + 500 + 1,000)
  "totalPrice": 12000 // calculatedUnitPrice * quantity (2개)
}

```

## 6. 향후 과제 및 알려진 한계점 (Future Scope & Known Limitations)

현재 버전은 핵심 기능 검증을 위한 MVP(최소 기능 제품)이므로, 빠른 출시와 사용성 확보를 위해 아래 항목들은 전략적으로 구현을 연기(Defer)하였으며 추후 고도화(v2) 시 반영할 예정입니다.

1. **동시성 제어 및 초과 판매(Over-selling) 방지**
   * **한계점:** 여러 사용자가 동시에 마지막 남은 한정 수량 디저트를 주문할 경우, DB 락(Lock) 미적용으로 인해 초과 접수될 가능성이 존재함.
   * **현재 대처안:** 단일 매장 MVP 특성상 발생 확률이 낮으며, 발생 시 관리자가 현황판에서 주문 취소 처리로 대응.
   * **향후 계획:** 트래픽 증가 시 트랜잭션 격리 수준 상향 또는 낙관적 락(Optimistic Lock) 도입.

2. **어뷰징 및 무단 스팸 주문 방지**
   * **한계점:** 결제 연동(PG)이 없어 악의적인 봇(Bot) 스크립트에 의한 대량 가짜 주문 테러에 취약함.
   * **현재 대처안:** 사용자 경험(빠른 주문)을 해치지 않기 위해 캡차(reCAPTCHA)나 SMS 인증을 제외함. 스팸 발생 시 관리자가 수동으로 취소하는 방식으로 운영.
   * **향후 계획:** 본격적인 운영 단계 진입 시 IP/디바이스 기반 Rate Limiting 구축 또는 최소한의 본인 인증 허들 추가.
